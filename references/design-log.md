# Design log (read before execution choices and after delivery)

## Purpose
Avoid repeating an execution shell across sessions, not merely the same
subject or medium. Use an existing persistent design log when reachable;
otherwise choose one stable `experience-design-log.md` in the permitted
saved-output/project location and record its actual path in session context.
Do not write inside the installed skill by default or search unrelated
folders for history. Record only design choices, not visitor input.

## Before finalizing concepts
Read this guidance before concept execution choices, not only after
delivery. If the known log exists, skim recent entries. Also use relevant
examples the person supplied; a log is not the only valid evidence.

Compare subject/medium, composition and subject scale, navigation,
primary action/controls, and during/after feedback. Different companies,
palettes or models can still share an identical execution. Keep old
short-format entries usable; do not invent missing fields.
For showcases, include imagery dominance and framing in composition notes:
did the actual asset lead the scene or remain inside an inherited UI box?
Do not measure visual richness by decorative element count.

For a selected concept or execution-only revision, keep the idea and frozen
requirements. Adjust repetitive staging or choreography rather than
reopening four concepts. Retain useful conventions with a brief task or
accessibility reason; no novelty quota or random selection is required.
Record what differs and what is deliberately reused in the existing
direction contract. If a user chose a familiar pattern, respect that choice.

## After delivery
Append one line to the log:
```
YYYY-MM-DD | <company/subject> | <medium> | <composition/scale> | <navigation> | <primary action/controls> | <during/after feedback> | <distinctive execution and justified reuse>
```

## When there's no persistent location
If no suitable persistent location exists, skip logging and say comparison
is limited to supplied examples/current-session work, if any. Continue
designing from the subject; do not block the build, invent a history or
claim cross-project originality without evidence.
